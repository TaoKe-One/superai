# 常见问题

[English](faq.en.md) · [使用手册](index.md)

## 局域网其他设备打不开网页

先在部署机运行 `curl http://127.0.0.1:8787/healthz`。本机能访问时，在另一台设备使用部署机的局域网 IP 检查同一个路径。如果超时，检查 Docker 是否发布到 `127.0.0.1`、使用的宿主机端口是否正确，以及防火墙是否放行该端口。调整 Docker 端口时重建容器并沿用原数据卷。[局域网配置](deployment.md#局域网访问)

## 搜得到歌曲或排行榜但播不出来

在「播放器 → 音乐源管理」查看音源是否启用、是否支持目标平台以及检测结果。用同一首歌和同一音源复测。排行榜空白时先切换目录平台，再检查部署机能否访问该平台的目录接口。私人库异常时，检查服务器地址、认证信息或 WebDAV 扫描状态。[音乐来源设置](usage.md#连接音乐库和音源)

如果 LX 检测明确提示 Fake-IP，v0.1.1 Docker 镜像默认启用了加密 DNS。已有容器显式设置为 `false` 时，改成 `LX_DNS_OVER_HTTPS=true` 后重建。若部署网络无法访问加密 DNS，则配置能够返回真实公网地址的系统 DNS。[v0.1.1 发布说明](https://github.com/TaoKe-One/superai/releases/tag/v0.1.1)

## 网页能播但音箱没声音

确认「音箱设备」中的目标音箱在线。私人库投放需要填写音箱可访问的平台地址，使用宿主机的局域网 IP 和映射端口。网页能播放而投放受理后进度始终为零时，检查音箱能否访问音频地址。部分固件可用歌曲地址转跳。[音频转跳配置](deployment.md#音箱收到投放后没有声音)

## 扫码后看不到音箱

确认手机小米账号与平台使用的账号一致，随后在「音箱设备」刷新设备列表。如需收集进一步诊断，可将 `MIOT_LOGIN_DIAGNOSTICS` 临时设为 `true`，复现后关闭。

## 小爱仍在自己回应或没有读出 AI 回答

到「音箱设备 → 语音接管与诊断」查看处理记录。没有收到记录时，检查监听开关、小米账号及音箱型号。收到记录后，按意图、模型生成和播报回执排查。家电和红外指令由小爱处理。由于平台从云端读取对话，小爱可能先发出原生回答。

## 测试模型或问答提示 HTTP 400

在「平台设置 → AI 模型」核对厂商、API 地址、当前账号可调用的模型名和密钥。使用厂商提供的 API 基础地址，保存前重新测试。测试通过而偶发失败时，记录触发时间、模型、部署版本和脱敏错误，检查部署机到模型服务的网络。从网页 AI 助手发送简短问题可先验证模型路径。

## 音乐会下载到本地吗

在线曲目由音源解析播放地址，私人曲库音频按需代理或转码。状态文件保存配置、队列、收藏、历史和歌单等信息。WebDAV 扫描保存曲库索引。浏览器的普通媒体缓冲由浏览器管理。[数据目录与备份](deployment.md#持久化和备份)

## WebDAV 音频转码失败

Docker 镜像自带 FFmpeg。命令行部署可执行 `ffmpeg -version` 检查是否可用，或用 `FFMPEG_PATH` 指定 FFmpeg 可执行文件。

## 忘记密码或重建容器后看到初始化页面

忘记密码时，在 v0.1.1 容器中使用密码恢复命令。如果重建容器后出现初始化页，先检查 `/data` 挂载的是否是原数据卷。Compose 会根据项目名生成卷名，移动目录时须沿用旧项目名或明确指定已有卷。迁移时同时保留 `state.json` 与原密钥配置。[密码恢复](deployment.md#忘记管理员密码) · [持久化和备份](deployment.md#持久化和备份)

提交问题时附上部署方式、版本、复现步骤及脱敏日志。涉及音箱请附型号和固件版本。[在 GitHub 提交问题](https://github.com/TaoKe-One/superai/issues)
